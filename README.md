# Farol.IA

## Backend real (Supabase + Vercel)

A interface agora usa `/api/profile` e `/api/applications`; não usa `localStorage` para persistir perfil ou candidaturas. As funções em `api/` são compatíveis com Vercel Serverless Functions.

### 1. Criar as tabelas no Supabase

```sql
create table profiles (
  email text primary key,
  nome text, telefone text, "dataNascimento" text, formacao text, instituicao text,
  funcao text, area text, experiencias text, idiomas text, cursos text,
  "cursosSalvos" jsonb default '[]'::jsonb,
  created_at timestamptz default now(), updated_at timestamptz default now()
);

create table applications (
  id bigint generated by default as identity primary key,
  email text not null,
  job jsonb not null,
  missing jsonb default '[]'::jsonb,
  status text default 'Salva',
  created_at timestamptz default now()
);
```

Em produção, substitua o uso de `SUPABASE_SERVICE_ROLE_KEY` por autenticação de usuário e políticas RLS. A implementação atual identifica o perfil pelo e-mail, suficiente para protótipo, mas não para dados sensíveis em produção.

### 2. Configurar a hospedagem

Na Vercel, importe este repositório e cadastre:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

O arquivo `index.html` pode continuar sendo servido pela Vercel. Depois do deploy, a aplicação salva e consulta dados no Supabase entre dispositivos.

> O GitHub Pages sozinho é apenas hospedagem estática e não executa as funções `/api`; use Vercel, Netlify Functions ou outro host com suporte a serverless.
